# СЕЙЧАС — сайт мировых новостей

В репозитории два самостоятельных Cloudflare Pages сайта:

- `site/` — основная новостная лента, новости API и геоблокировка.
- `admin-site/` — отдельный редактор новостей на собственном адресе, с отдельной геоблокировкой.

## Локальный запуск

Требуется Node.js 18+ и Wrangler. Запустите основной сайт из корня репозитория:

```bash
npx wrangler pages dev ./site --port 8788
```

Админка — отдельным сервером в другом терминале:

```bash
npx wrangler pages dev ./admin-site --port 8789
```

Чтобы локальная админка могла обращаться к локальному API, в `site/.dev.vars` укажите локальный адрес панели и тестовый пароль. Если подключаете локальную D1, добавьте аргумент `--d1 NEWS_DB=<database-id>` к команде основного сайта. `.dev.vars` игнорируется Git и не должен попадать на GitHub.

Пример `site/.dev.vars` для локальной пары сайтов:

```text
NEWS_ADMIN_ORIGIN=http://localhost:8789
NEWS_ADMIN_PASSWORD=local-test-password
```

## Загрузка двух сайтов из одного GitHub-репозитория

Создайте приватный GitHub-репозиторий и загрузите в него весь проект. Затем в Cloudflare Dashboard подключите его **дважды**, создав два Pages-проекта:

| Pages-проект | Root directory | Build output directory | Адрес по умолчанию |
|---|---|---|---|
| `seychas-world-news` | `site` | `.` | `https://seychas-world-news.pages.dev` |
| `seychas-editor` | `admin-site` | `.` | `https://seychas-editor.pages.dev` |

Для обоих проектов оставьте Build command пустой. Cloudflare Pages поддерживает несколько проектов из одного репозитория с разными корневыми папками и автоматически разворачивает их после push.

Файл `admin-site/config.js` указывает адрес основного сайта. Если имя проекта или домен отличается, обновите там `SEYCHAS_API_BASE`. В основном Pages-проекте задайте переменную `NEWS_ADMIN_ORIGIN` точно равной адресу админ-сайта, например `https://seychas-editor.pages.dev`.

## Сохранение новостей и вход

Новости сохраняются в Cloudflare D1 и сразу попадают в основную ленту. При первом входе пустая база заполняется десятью демонстрационными новостями. Админ-сайт открывается по корневому адресу своего домена.

1. Войди в Cloudflare через Wrangler и создай базу: `npx wrangler d1 create seychas-news`.
2. Из папки `site` выполни миграцию: `npx wrangler d1 migrations apply seychas-news --remote`.
3. В настройках основного Pages-проекта добавь D1 binding с именем `NEWS_DB` и выбери базу `seychas-news`. После сохранения заново разверни проект.
4. В **Settings → Variables and Secrets** основного проекта задай `NEWS_ADMIN_ORIGIN` и секрет `NEWS_ADMIN_PASSWORD` с длинным уникальным паролем. Сохрани и заново разверни проект.
5. Открой отдельный адрес админ-проекта, например `https://seychas-editor.pages.dev/`, и войди.

API принимает административные запросы только с точного origin, заданного в `NEWS_ADMIN_ORIGIN`, и только с правильным паролем. Пароль хранится как Cloudflare Secret, не в коде.

Чтобы допускать ровно один аккаунт, дополнительно подключи к админ-сайту собственный домен и закрой его Cloudflare Access политикой **Allow → Emails → твой email**. Оставь также пароль панели включённым. Сам `admin-site/` лучше хранить в приватном GitHub-репозитории.

## Геоблокировка

В `site/functions/_middleware.js` и `admin-site/functions/_middleware.js` проверяется IP-страна на сервере. Запросы с кодом `KG` получают HTTP 403 и страницу с предоставленным изображением; остальные проходят. Для дополнительных стран измени `BLOCKED_COUNTRIES = ["KG"]`. Локальный запуск сам по себе не знает страну IP; рабочая проверка происходит на Cloudflare Pages.

## Переменные и секреты

- `NEWS_DB` — D1 binding в основном Pages-проекте.
- `NEWS_ADMIN_ORIGIN` — обычная переменная основного проекта с origin отдельной админки.
- `NEWS_ADMIN_PASSWORD` — зашифрованный Cloudflare Secret для входа в панель.

RSS/API ключ не нужен: сайт стартует с демо-новостями, которые можно редактировать в админке.
